# Запуск с Codex на Windows

Бот и Codex запускаются под одной учётной записью Windows. Бот получает
сообщения через Telegram long polling: ему нужен исходящий доступ в интернет,
белый IP, открытые порты и VPS не нужны. Компьютер должен оставаться включённым.

## Подготовка

Установите Python 3.12 или новее и Codex CLI либо Codex Desktop. В PowerShell
из каталога проекта:

```powershell
py -3.12 -m pip install --user uv
py -3.12 -m uv sync --group dev
Copy-Item .env.example .env
```

В `.env` заполните `TELEGRAM_BOT_TOKEN` и `ALLOWED_USER_IDS`. Для русского
интерфейса укажите `BOT_LANG=ru`. Чтобы личный чат работал с вашим проектом,
укажите его абсолютный Windows-путь в `DEFAULT_CWD`. Например:

```dotenv
TELEGRAM_BOT_TOKEN=токен-от-BotFather
ALLOWED_USER_IDS=[123456789]
BOT_LANG=ru
DEFAULT_CWD=C:\Users\me\projects\my-app
FILE_CACHE_DIR=./data
```

Проверьте, что Codex уже авторизован **под той же учётной записью Windows**:

```powershell
codex --version
codex login status
```

Запустите бота:

```powershell
.\scripts\start-windows.ps1
```

Либо напрямую: `.\.venv\Scripts\python.exe -m telegram_bot`. При первом
сообщении бот сам обнаружит Codex: установленный вместе с Desktop `codex.exe`
или CLI `codex.cmd`. Указывать `TELEGRAM_CODEX_BIN` обычно не требуется.

## Сессии CLI и Desktop

Бот запускает Codex CLI с тем же `CODEX_HOME`, что и пользовательский Codex.
В личном чате команда `/resume` показывает сохранённые чаты Codex из всех рабочих
папок. Нажмите номер чата, чтобы бот переключился на него и продолжил работу.
Рабочая папка переключится вместе с чатом. В forum topics список остаётся
ограниченным рабочей папкой темы.
Для поиска по названию чата или проекту используйте `/resume <слово>`.
Если выбранный чат уже используется другим процессом Codex, бот сохранит выбор
и сообщит об этом; остановите другой запуск и повторите сообщение.

Новый чат в обычном режиме создаётся через Codex app-server и появляется в
Codex Desktop. Последующие сообщения идут через `codex exec resume` в тот же
чат. Команды `/new` и `/clear` начинают новый чат при следующем сообщении.
Цель текущего чата доступна через `/goal`: `/goal set <цель>`, `/goal pause`,
`/goal resume`, `/goal complete`, `/goal budget <токены>`, `/goal clear`.

На Windows доступны оба режима из исходного проекта:

- `subprocess` запускает Codex на каждое сообщение и сохраняет контекст по
  session ID.
- `tmux` в файле настроек (кнопка `TUI (ConPTY)` в `/mode`) означает
  постоянную интерактивную TUI-сессию.
  На Windows за ней стоит локальный ConPTY-процесс, а на Linux — обычный
  `tmux`. Сессия переживает перезапуск бота. Команда `/tui` показывает экран
  Codex и даёт кнопки для клавиш, `/kill` завершает сессию, `/recycle`
  перезапускает её с сохранением контекста.

В forum topic выберите режим через `/mode`. На Windows бот сам запускает
локальный терминальный процесс и подключается к нему; отдельный сервер,
WSL и белый IP не нужны. Desktop используется через установленный вместе с
ним `codex.exe` и общие файлы сессий. Бот может продолжить сохранённую
сессию Desktop, но не управляет уже открытым окном Desktop напрямую.

## Проверка без Telegram-токена

Чтобы проверить локальное подключение к Codex и продолжение диалога до
настройки Telegram, запустите:

```powershell
.\.venv\Scripts\python.exe scripts\smoke-windows-codex.py
```

Проверка запускает два коротких запроса через тот же `SessionManager`, что и
бот, и подключает MCP-сервер с тестовым токеном. Для проверки доставки
сообщений и файлов в настоящий Telegram нужен токен в `.env` и чат с ботом.

Проверка интерактивной TUI-сессии через ConPTY:

```powershell
.\.venv\Scripts\python.exe scripts\smoke-windows-tui.py
```

При первом запуске Codex может показать запрос доверия к рабочей папке. Подтвердите его
локально, затем повторите проверку. Скрипт ждёт ответ Codex и завершает тестовую сессию.

Проверка отправки сообщения и документа в **настоящий Telegram** через встроенный
MCP-сервер (использует `.env` и первый ID из `ALLOWED_USER_IDS`):

```powershell
.\.venv\Scripts\python.exe scripts\smoke-telegram-mcp.py
```

Этот скрипт отправляет два сообщения в личный чат. Не запускайте его как часть
автоматических тестов.
